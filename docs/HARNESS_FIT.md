# Harness.io: fit for this project

Checked October 9, 2026 through Exa on Alex's newly connected Composio Exa account. Alex confirmed that “harnus.io” meant Harness.io. This is research, not an installation or a claim that Alex has an enabled Harness account.

## Recommendation

Keep Harness outside the first local app build. Evaluate a small telemetry or software-delivery integration later if it replaces a demonstrated gap. It does not remove the immediate need for Alex's source reconciliation, arbitrary local-file relationships or correction/recovery contract. This recommendation is an inference from the documented product scope, not a tested rejection of Harness.

| Harness capability | Verified vendor description | Possible value here | Still unknown for Alex |
| --- | --- | --- | --- |
| Software Delivery Knowledge Graph | Connects Git, delivery pipelines, cloud/runtime/security/cost context with canonical identities and governed retrieval | Future deployed-service dependency and incident context | Import/export of this catalog, arbitrary local files/1Password metadata/Composio routes, account entitlement, coverage and price |
| AgentTrace | Collects typed LLM/tool/retrieval/agent spans; relates tracing to evaluations | Show what an instrumented agent actually did and turn failures into regression cases | Actual visibility into each existing agent, SDK receipt linking, instrumentation needed, retention and pricing |
| AI DLC Agent | Separate workstation daemon for coding-tool telemetry, with Cursor support documented | Measure usage, cost estimates and code attribution | Required account/module access and collection scope acceptable for this Mac; not installed |
| Harness Cursor plugin | Vendor docs describe bundled Harness skills, MCP tools, rules and hooks for Harness resources | Avoid hand-writing Harness-specific integration procedures if Harness is adopted | Harness account/OAuth enablement, compatibility with Alex's approved Composio route, target-runtime proof |

The two AgentTrace product URLs are not perfectly aligned: `/agenttrace` marks the full execution graph “In Development,” while `/agent-trace` describes it without that label. Treat the feature's availability as unconfirmed until account-level documentation or a live trial resolves this. Do not promise a complete execution graph from marketing text alone.

## Sources and boundaries

- [Knowledge Graph](https://www.harness.io/products/platform/knowledge-graph): software delivery context and integration categories. Vendor positioning is not evidence of coverage of Alex's whole business/agent setup.
- [AgentTrace](https://www.harness.io/products/platform/agenttrace) and [alternate AgentTrace page](https://www.harness.io/products/platform/agent-trace): tracing, eval linkage and open-source collection/evaluation claims. Collection libraries are described as exporting OTLP; no libraries were installed or exercised here.
- [AI DLC Agent documentation](https://developer.harness.io/ai-dlc-insights/use-ai-dlc-insights/setup/agent/index): workstation telemetry, module/account prerequisites, metadata vs optional prompt/response collection. This is separate from durable job recovery.
- [Cursor plugin](https://developer.harness.io/docs/platform/harness-ai/cursor-plugin/) and [Hosted MCP](https://developer.harness.io/harness-platform/use-harness-ai/connect-with-ai/index/hosted-mcp): account OAuth must be enabled; SaaS entitlement affects available tools. Documented skill/tool counts differ across pages; rely on actual installed discovery before implementation.

No account was created, subscription purchased, daemon installed, credential obtained, data uploaded, remote MCP enabled, or Harness skill activated. The plugin's broad delivery/secret/role operations are not needed for this local viewer build. An adoption request would first use Alex's existing connector-route procedure and a named account, rather than copying the vendor's API-key examples into local files.

## A future bounded proof, if Alex chooses adoption

Choose one real missing question, such as “which repeated tool calls caused this job to waste time?” Feed a sanitized sample through a permitted read-only or test route and verify: source identity, job/task/attempt correlation, restart behavior, exportability, redaction, known cost, and benefit over the existing SDK receipts. Do not migrate the catalog or workflow store until that proof shows the replacement meets the same acceptance contract.
