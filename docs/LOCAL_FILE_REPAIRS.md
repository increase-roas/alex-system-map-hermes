# Review and fix local instructions

Alex requested a button to fix contradictory or unnecessary local instructions (2026-10-20), then extended it to AI-written proposed fixes that he can approve. Scanning and AI analysis stay read-only; only an explicit Apply action writes the exact reviewed source change. AI uses the installed Codex CLI and existing ChatGPT plan login, subject to its usage limits. No new paid API account, Claude review, dependency, background job, hook or policy guard is authorized. The current AI behavior and acceptance are in LOCAL_FILE_AI_PROPOSALS.md. Reuse the local request/token boundary, Python standard library and native Git.

The operation is an exact text repair of handwritten Markdown rule sources. Review & fix is available from file detail and instruction evidence. Generated files navigate to indexed source references. Shared links are identified as intentional aliases; no delete or replacement of aliases. Configs, executable hooks, provider-managed files and skills needing their separate validation workflow show an explanation rather than a generic file write. AI proposes only validated replacements grounded in current source evidence and creates a frozen preview for approval. Unsupported or unresolved authority produces an explanation without an approvable change. The optional manual editor starts from the actual source.

For manual repairs, Use this wording lets Alex choose the other evidence excerpt and substitutes only the exact, uniquely matching target evidence line in a clean current draft. It preserves other bytes/newline style, refuses stale or ambiguous text and never overwrites an existing draft. This manual choice makes no automatic authority judgment. AI is now the default proposal path, with its recommendation and evidence visible before approval.

Editable locations: handwritten .md/.mdc/.txt sources under ~/.agents/instructions, ~/.claude/rules, ~/.cursor/rules, ~/Alex-Director/rules, plus nongenerated ~/AGENTS.md, ~/Alex-Director/AGENTS.md and ~/AGENT-CONTEXT.md. All must already be indexed, readable, within selected roots, unredacted, regular canonical files at unchanged resolved targets and at most 64 KiB. Symlink paths may navigate to the canonical source but may not be rewritten directly. No source writes during development acceptance: use private temporary home + bare Git remote fixtures.

Reuse native Git for durability. Before apply, establish that the file's exact before bytes are tracked, unmodified in the index and HEAD, and HEAD equals the current branch's origin remote ref (read with Git, no force/fetch/reset/branch switching). If the preimage is not already backed off machine, return a clear actionable reason and leave source unchanged. Also save exact bytes/mode in ~/Backups/local-file-repairs (the existing Drive location), verify and fsync before replacement. This Drive copy is an undo copy; do not claim cloud upload was verified. Source CAS compares the displayed hash and the frozen preview again immediately before atomic replacement. Preserve modes, reject path/link swaps, secrets and stale proposals.

After source replacement, verify exact readback, commit only that path with native git commit --only and push its current branch without force. Do not stage or commit others' work. If the commit/push fails, record and show source-applied/publish-pending, preserve recovery, never claim complete or automatically retry a side effect. An Undo action restores only the exact recorded preimage if the current file still matches the recorded applied hash, then records/commits/pushes the restoration. No automatic rollback over a third-party edit. Repeated Apply/Undo requests reconcile recorded state rather than repeat effects.

Generated distribution stays explicit. The broad native build_instructions.py apply also writes app-owned Codex settings; this feature must not silently run it. The existing ~/.agents post-commit hook was found to invoke that broad operation, so the prerequisite native fix changes that hook to an explicit rules-only operation that preserves Codex config bytes. Keep normal repository hooks enabled. Their asynchronous rule/notes publication may run after the one-path commit; the file-repair response reports source updated with generated-publication verification pending. A successful push does not verify hook publication. A fresh scan updates evidence; it does not declare every contradiction resolved.

API: GET /api/local-files/repair?id=<indexed id> returns LocalRepairSource; local-token POST accepts {action:'preview',file_id,expected_sha256,new_content}, {action:'apply',repair_id,proposal_sha256}, or {action:'undo',repair_id}. No client paths, commands, backup paths or arbitrary roots. Body <=192 KiB; sources <=64 KiB. Proposal/receipt bytes are private app/.data state, never raw request logs or public receipts. Every operation returns JSON with truthful state and stable errors; unavailable source is readable/actionable, stale edits 409, malformed input400, unauth401, nonlocal403. Refresh doesn't overwrite a user's unsubmitted draft.

Acceptance:
1. Review & fix opens current source text and both evidence excerpts; generated/managed/link cases route to the owner or explain why a direct write is unavailable.
2. Preview shows the exact proposed before/after change, source path and fingerprint, and applies only that frozen proposal after explicit Apply. AI recommendations are identified and justified with current citations; Alex retains approval. Manual editing remains optional.
3. Before a write, exact durable Git preimage and verified undo copy exist; file/token/path/body/secret and stale-proposal boundaries hold. Failures leave source unchanged before replacement.
4. Apply changes one intended source, preserves mode, verifies readback, commits/pushes only it and reports any publish or generated-distribution follow-up. Retries reconcile state. Other staged/dirty work is preserved.
5. Undo restores the bound preimage only if the applied source is unchanged; newer edits are protected. Restore/publish failure is visible.
6. Focused real temporary Git fixtures prove apply, exact backup, remote commit/readback, undo, stale edits, symlink/managed/secret/unsupported refusal and unrelated staged/dirty preservation. One final TypeScript check and real desktop/narrow browser journey bind the final code. No actual agent source edits in acceptance.
