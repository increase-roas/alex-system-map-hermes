## Interface

POST /api/local-files/repair adds `{action:'suggest', file_id, expected_sha256, finding_id: string|null}` under the existing local/token/body boundary. The server resolves all paths/context; no client prompt, model, command or source body.

`LocalRepairSuggestion` contains `status` (`proposed`, `no_change`, `needs_decision`), `summary`, `rationale`, `conflicts` (explanation plus exact citations), `limitations`, `context_files` (IDs/paths/hashes), `model`, `generated_at`, `proposed_content: string|null`, and `preview: LocalRepairPreview|null`. Citations are `{file_id,line,quote}`. Only a valid proposed status with passed behavioral checks has content and a frozen preview. Suggestion adds checks, context_files includes evidence-derived applicability, and preview/result distribution fields follow APPROVED_RULE_REPAIR.md.

The worker schema uses the same analysis fields plus `edits: {old_text,new_text}[]`, never full file paths or commands. The server applies uniquely matching nonoverlapping replacements to its own target snapshot, validates the result and generates the existing preview. The server context sets `canonical_gate_file_id` only when the configured canonical gates file is actually included, otherwise null. This authority designation follows Alex's current instruction identifying his canonical approval list, rather than claims embedded in source files. A separate prompt header identifies that file as authority only for overlapping actions and scope expressly covered by the supplied policy. It is an analytical precedence hint, never runtime authority or permission to act. A supported scoped exception permits a minimal narrowing proposal while preserving all other gates and protections. Unrelated ambiguities remain unchanged and are disclosed; they do not block an independently supported subset. Historical quotations remain quotations. Use needs_decision when no justified scoped edit is possible, never invent permissions, broaden an exception or silently remove a gate. Every proposed edit still requires the existing explicit frozen approval.

## Checked approval flow (2026-10-21)

APPROVED_RULE_REPAIR.md supersedes the earlier source-only generation-pending behavior. A separate tool-free planner proposes 2-4 multiple-choice cases with exact current citations, covering the intended repair and preserved behavior. Independent before/candidate runs receive the scenarios and options without the expected answers. Unknown choices, malformed output, unavailable testing or failed comparisons yield no approvable AI preview. Reported tests are bounded simulated instruction decisions, not live execution or universal consistency. Before results are shown even if they also passed; do not claim a measured behavior improvement from identical choices. Changing a manual draft invalidates its AI checks; manual previews remain visibly untested.

Optional adjacent source/ownership context cannot silently become authority. Required selected finding evidence remains required; unsuitable optional references are omitted with explicit limitations. Shared aliases and generated_from relations help distinguish derivative copies from independent policy. Context limits remain eight files /128 KiB. The source, relevant evidence and native generation inputs must still match at approval.

For supported native instruction sources, trusted context includes a conservative UTF-8 candidate ceiling derived from the current native document budget. The proposer must fit it and prefer concise canonical references. Validation rejects an oversized candidate before behavioral calls. Native candidate rendering still enforces the configured limit, including when a shrinking repair starts from an oversized baseline. No app settings or byte limits are changed. A size failure returns an actionable 422 rather than falsely reporting stale source.

The proposer and case planner receive a prompt-only view with explicit source line numbers and original per-line endings. Exact raw source context, citation validation and the before/candidate decision inputs remain unchanged. Exact multiline edits can retain LF, CRLF, mixed endings and missing final newlines. The server never repairs an incorrect citation automatically. Failed or unavailable checks identify their stage; they do not imply Alex must choose the wording or authority when the actual failure was testing.
